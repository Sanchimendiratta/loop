# Loop Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Loop — the XLRI alumni job-post and referral network — covering all of PRD §7.1 Must plus the post→request bridge, with a two-sided tracker and no seeker-side caps.

**Architecture:** Pure TypeScript domain modules in `src/core/` hold every rule and are unit-tested with no DOM. One repository boundary, `src/data/store.ts`, is the only module that touches persistence and the only place four non-bypassable rules live (privacy, duplicate-submission, referrer capacity, state transitions). `src/ui/` is React screens that read and write solely through that boundary.

**Tech Stack:** React 19, TypeScript, Tailwind 4, Vite 8, Vitest.

**Spec:** `docs/superpowers/specs/2026-09-16-loop-design.md`

## Global Constraints

- **Node >= 20.** Package is ESM (`"type": "module"`).
- **No network at runtime.** No LLM call, no Supabase, no scraping. A pasted LinkedIn URL is text that is never fetched (spec §14).
- **`src/core/` imports nothing** outside itself and `src/data/schema.ts`. No React, no store, no browser globals. This is what keeps it unit-testable.
- **No UI module touches `localStorage`.** Every read and write goes through `src/data/store.ts` (spec §4).
- **Privacy is a read-time filter.** Every store read takes the viewing member and returns only what they may see (spec §7). An unverified member's read returns empty, never a redirect.
- **A low-confidence parsed field renders empty, never guessed** (spec §5). `MIN_CONFIDENCE = 0.5`.
- **The disclosure sentence is composed in one module.** No component builds its own (spec §6).
- **No seeker-side caps.** No max-open-requests, no per-company cap, no closure block (spec DL1). The only retained guard is one seeker + one role + one submission.
- **Terminology in user-facing copy:** "alum"/"alumni", not "user". "Refer", not "recommend". A post's poster is the "poster"; the person inside the company on a request is the "referrer".
- **Every commit** runs `npm run verify` before it is made.

```ts
/**
 * Day arithmetic.
 *
 * Every window in this product is measured in calendar days, not business
 * hours: a referral sits with a referrer over a weekend just as it does midweek,
 * and a post ages the same way. That is the opposite of Pipelined's SLA clock,
 * and deliberately so — this side of the market is unpaid volunteers, not staff
 * on a working week.
 */
export const DAY_MS = 86_400_000;

/** Whole days elapsed, floored, never negative. */
export function daysBetween(from: number, to: number): number {
  if (to <= from) return 0;
  return Math.floor((to - from) / DAY_MS);
}

export function addDays(at: number, days: number): number {
  return at + days * DAY_MS;
}

/** Local midnight for the day containing `at`. */
export function startOfDay(at: number): number {
  const d = new Date(at);
  d.setHours(0, 0, 0, 0);
  return d.getTime();
}
```

`src/core/privacy.ts`:
```ts
/**
 * Viewer-scoped visibility (D2, D6).
 *
 * This is the stand-in for the row-level security PRD §9 puts in Postgres. It
 * is expressed as filters rather than guards because the failure mode of a
 * guard is an exception a caller can swallow, while the failure mode of a
 * filter is an empty list — which is the correct answer for someone who may
 * not see a thing. D2 is explicit that an unverified account sees nothing:
 * that is not a redirect to a sign-up page, it is an empty result.
 */
import type { Member, ReferralRequest } from '../data/schema.ts';

export function isVerified(m: Member | null): boolean {
  return Boolean(m && m.status === 'verified');
}

export function canSeeNetwork(m: Member | null): boolean {
  return isVerified(m);
}

/**
 * A seeker's confidentiality is enforced on the *target*, not the viewer:
 * Karan (§4) blocks his employer, and it is his record that must refuse to be
 * rendered, wherever it is asked for.
 */
export function canSeeMember(viewer: Member | null, target: Member): boolean {
  if (!canSeeNetwork(viewer)) return false;
  if (viewer!.id === target.id) return true;
  // A seeker's block binds every viewer, admins included. §8 grants the control
  // without exception, and the sharp case is a seeker blocking a manager who
  // also holds an admin seat — an admin carve-out the seeker is never told about
  // would make the promise false. Admin moderation does not route through
  // profile visibility: it reads verification cases and reports, where the
  // member either submitted the evidence themselves or is named in a report.
  // `canSeeRequest` keeps its admin carve-out, because D6 states that one.
  if (target.privacy.blockedMemberIds.includes(viewer!.id)) return false;
  if (viewer!.companyId && target.privacy.blockedCompanyIds.includes(viewer!.companyId)) return false;
  return true;
}

}

  if (!canSeeNetwork(viewer)) return [];
  return all.filter((r) => canSeeRequest(viewer, r));
}

  return canSeeNetwork(viewer);
```

```ts
/**
 * Membership verification (§6).
 *
 * D2 makes this the whole product: "a referral network that lets anyone in is
 * LinkedIn." Tier A is a domain fact and is therefore instant. Tier B is a
 * human judgement over a self-declared LinkedIn education entry — §6 is candid
 * that this is a plausibility check, not proof — so every decision carries a
 * reviewer, a timestamp and a reason, and rejection is appealable once.
 */
import { VOUCHING_UNLOCK_THRESHOLD } from '../data/schema.ts';
import type { School, VerificationCase, VerificationTier } from '../data/schema.ts';

/**
 * Tier A iff the address's domain is exactly an allowlisted one.
 *
 * Suffix matching would admit `astra.xlri.ac.in.example.com`, which is the
 * cheapest possible forgery of the one signal we treat as proof.
 */
export function tierForEmail(email: string, school: School): VerificationTier | null {
  // Exactly one '@', and the domain is what follows it.
  //
  // `split('@')[1]` is NOT the same thing and is a real bypass: for
  // `attacker@astra.xlri.ac.in@evil.com` it returns the allowlisted middle
  // segment while the address actually delivers to evil.com — granting instant
  // verification to a forged address, on the one signal this product treats as
  // proof. Requiring a single '@' rejects malformed input instead of guessing
  // which part of it to trust.
  const parts = String(email ?? '').trim().toLowerCase().split('@');
  if (parts.length !== 2) return null;
  const domain = parts[1];
  if (!domain) return null;
  return school.verifiedDomains.some((d) => d.toLowerCase() === domain) ? 'A' : null;
}

export function decideCase(
  c: VerificationCase,
  decision: 'approved' | 'rejected' | 'more_info',
  reviewerId: string,
  at: number,
  notes: string,
): VerificationCase {
  return { ...c, decision, reviewerId, decidedAt: at, notes };
}

/** §6: one appeal, with documentary evidence, reviewed by a second admin. */
export function canAppeal(c: VerificationCase): boolean {
  return c.decision === 'rejected' && !c.isAppeal;
}

export function vouchingUnlocked(verifiedCount: number): boolean {
  return verifiedCount >= VOUCHING_UNLOCK_THRESHOLD;
}

  return 2;
}
```

```ts
/**
 * Paste-to-parse (D12).
 *
 * PRD §9 assigns the hard judgements to an LLM behind a JSON schema. There is
 * no model here (spec DL5), so this is the deterministic layer §9 requires
 * first, built behind an interface a model can satisfy later.
 *
 * The governing rule is §9's: the parser never publishes. It pre-fills a form a
 * human confirms, and **a low-confidence field renders empty rather than
 * guessed** — a wrong value a hurried poster accepts is worse than a blank one.
 * That is why every field carries a confidence and why `parseField` nulls the
 * value below the threshold rather than leaving the caller to remember.
 */
import type { ApplyMethod, DestinationType } from '../data/schema.ts';

export const MIN_CONFIDENCE = 0.5;

export interface ParsedField<T> {
  value: T | null;
  confidence: number;
  /** The slice of the paste this came from, so the composer can highlight it. */
  source: string | null;
}

export interface ParsedPost {
  title: ParsedField<string>;
  company: ParsedField<string>;
  locations: ParsedField<string[]>;
  experience: ParsedField<{ min: number; max: number }>;
  compensation: ParsedField<string>;
  applyMethod: ParsedField<ApplyMethod>;
  applyValue: ParsedField<string>;
  jdUrl: ParsedField<string>;
  destination: ParsedField<DestinationType>;
  raw: string;
  overallConfidence: number;
}

const none = <T>(): ParsedField<T> => ({ value: null, confidence: 0, source: null });

/** Single choke point for §9's rule: below the threshold, the value is gone. */
function field<T>(value: T | null, confidence: number, source: string | null): ParsedField<T> {
  if (value === null || confidence < MIN_CONFIDENCE) return { value: null, confidence, source };
  return { value, confidence, source };
}

const URL_RE = /https?:\/\/[^\s<>()]+/g;
const EMAIL_RE = /[\w.+-]+@[\w-]+\.[\w.-]+/g;
const PHONE_RE = /(?:\+91[\s-]?)?(?:\d[\s-]?){10}/g;
const RANGE_RE = /(\d{1,2})\s*[-–—]\s*(\d{1,2})\s*(?:\+)?\s*(?:yrs?|years?)/i;
const SINGLE_YEARS_RE = /~?\s*(\d{1,2})\s*\+?\s*(?:yrs?|years?)/i;

const PLATFORM_HOSTS = ['lever.co', 'greenhouse.io', 'workday', 'naukri.com', 'linkedin.com', 'indeed.', 'wellfound.com', 'instahyre.com'];
const RECRUITER_HINTS = ['search', 'talent', 'hunt', 'consultant', 'staffing', 'hiring', 'recruit', 'placement'];
const GENERIC_MAILBOXES = ['careers', 'jobs', 'hr', 'recruitment', 'hiring', 'apply', 'talent'];

const CITIES = [

  'Pune', 'Hyderabad', 'Chennai', 'Kolkata', 'Ahmedabad', 'Jaipur', 'Indore', 'Kochi', 'Chandigarh',
];
const REGIONS: [RegExp, string][] = [
  [/\bpan[-\s]?india\b/i, 'Pan-India'],
  [/\bremote\b/i, 'Remote'],
  [/\bhybrid\b/i, 'Hybrid'],
  [/\bmiddle east\b|\bME\b/, 'Middle East'],
  [/\bUK\b/, 'UK'],
  [/\bUS\b|\bUSA\b/, 'US'],

/** Seniority words map to a band only when no explicit range is given (§5.1). */
const SENIORITY: [RegExp, { min: number; max: number }][] = [
  [/\bchief\b|\bCXO\b|\bCBO\b|\bCEO\b|\bhead of\b|\bVP\b|\bvice president\b/i, { min: 15, max: 25 }],
  [/\bdirector\b|\bAD\b|\bassociate director\b|\bprincipal\b/i, { min: 12, max: 20 }],
  [/\bsenior\b|\blead\b|\bmanager\b/i, { min: 6, max: 12 }],
  [/\bassociate\b|\banalyst\b|\bexecutive\b/i, { min: 0, max: 3 }],
];

const lineContaining = (text: string, needle: string): string | null =>
  text.split('\n').find((l) => l.includes(needle))?.trim() ?? null;

function parseTitle(text: string): ParsedField<string> {
  const lines = text.split('\n').map((l) => l.trim()).filter(Boolean);
  if (!lines.length) return none();

  // A labelled line is the strongest signal.
  for (const line of lines) {
    const m = /^(?:role|position|title|hiring(?: for)?|opening(?: for)?)\s*[:\-]\s*(.+)$/i.exec(line);
    if (m) return field(m[1].trim(), 0.9, line);
  }
  // "X is hiring a Y" / "X is looking for a Y"
  for (const line of lines) {
    const m = /\b(?:is\s+)?(?:hiring|looking for|seeking)\s+(?:a|an)\s+(.+?)[.!]?$/i.exec(line);
    if (m) return field(m[1].trim(), 0.8, line);
  }
  // Otherwise the first line, minus decoration. Weaker, but §5.0 shows the
  // title is almost always the opener.
  const first = lines[0].replace(/^[^\p{L}]+/u, '').replace(/[:!]+$/, '').trim();
  const cleaned = /^(?:hiring|urgent|open(?:ing)?)\s*[:\-]?\s*/i.test(first)
    ? first.replace(/^(?:hiring|urgent|open(?:ing)?)\s*[:\-]?\s*/i, '').trim()
    : first;
  return field(cleaned || null, cleaned.length > 2 ? 0.6 : 0, lines[0]);
}

/**
 * Company extraction — deliberately conservative.
 *
 * Three of §5.0's five messages withhold the name on purpose. Producing a guess
 * for those ("impact-tech startup" is not a company) would be worse than
 * leaving it blank, so only two high-precision shapes are accepted.
 */
function parseCompany(text: string): ParsedField<string> {
  const lines = text.split('\n').map((l) => l.trim()).filter(Boolean);

  for (const line of lines) {
    const labelled = /^(?:company|organisation|organization|client)\s*[:\-]\s*(.+)$/i.exec(line);
    // "Our client is a …" is a withheld name, not a company name.
    if (labelled && !/^(?:a|an|our client)\b/i.test(labelled[1].trim())) {
      return field(labelled[1].trim(), 0.85, line);
    }
    const subject = /^([A-Z][\w&.'-]*(?:\s[A-Z][\w&.'-]*)?)\s+(?:is hiring|is looking for|is seeking|are hiring)/.exec(line);
    if (subject) return field(subject[1].trim(), 0.8, line);
  }
  return none();
}

function parseLocations(text: string): ParsedField<string[]> {
  const found: string[] = [];
  let source: string | null = null;

  for (const city of CITIES) {
    const re = new RegExp(`\\b${city}\\b`, 'i');
    if (re.test(text) && !found.includes(city)) {
      found.push(city);
      source ??= lineContaining(text, city);
    }
  }
  for (const [re, label] of REGIONS) {
    if (re.test(text) && !found.includes(label)) {
      found.push(label);
      source ??= text.split('\n').find((l) => re.test(l))?.trim() ?? null;
    }
  }
  if (!found.length) return none();
  return field(found, 0.85, source);
}

function parseExperience(text: string): ParsedField<{ min: number; max: number }> {
  const range = RANGE_RE.exec(text);
  if (range) {
    const min = Number(range[1]);
    const max = Number(range[2]);
    if (min <= max) return field({ min, max }, 0.9, lineContaining(text, range[0]) ?? range[0]);
  }
  const single = SINGLE_YEARS_RE.exec(text);
  if (single) {
    const min = Number(single[1]);
    return field({ min, max: min + 3 }, 0.7, lineContaining(text, single[0]) ?? single[0]);
  }
  for (const [re, band] of SENIORITY) {
    const m = re.exec(text);
    if (m) return field(band, 0.55, lineContaining(text, m[0]) ?? m[0]);
  }
  return none();
}

function parseCompensation(text: string): ParsedField<string> {
  const line = text.split('\n').find((l) =>
    /(?:₹|rs\.?|inr)\s*[\d.]|(?:\d+\s*[-–]\s*\d+\s*L\b)|\bLPA\b|\bESOP/i.test(l) ||
    /^(?:comp(?:ensation)?|ctc|salary)\s*[:\-]/i.test(l.trim()),
  );
  if (!line) return none();
  const stripped = line.replace(/^(?:comp(?:ensation)?|ctc|salary)\s*[:\-]\s*/i, '').trim();
  return field(stripped || null, 0.8, line.trim());
}

/** A route is required to publish, so email and phone beat a bare JD link. */
function parseRoute(text: string): { method: ParsedField<ApplyMethod>; value: ParsedField<string>; jd: ParsedField<string> } {
  const urls = text.match(URL_RE) ?? [];
  const emails = text.match(EMAIL_RE) ?? [];
  const phones = (text.match(PHONE_RE) ?? [])
    .map((p) => p.replace(/\D/g, ''))
    .map((d) => (d.length === 12 && d.startsWith('91') ? d.slice(2) : d))
    .filter((d) => d.length === 10);

  const jdUrl = urls.find((u) => /docs\.google|notion\.|\.pdf$|drive\.google/i.test(u)) ?? null;
  const applyUrl = urls.find((u) => u !== jdUrl) ?? null;

  if (emails.length) {
    const chosen = emails[0];
    return {
      method: field<ApplyMethod>('email', 0.95, lineContaining(text, chosen)),
      value: field(chosen, 0.95, lineContaining(text, chosen)),
      jd: jdUrl ? field(jdUrl, 0.9, lineContaining(text, jdUrl)) : none(),
    };
  }
  if (applyUrl) {
    return {
      method: field<ApplyMethod>('link', 0.9, lineContaining(text, applyUrl)),
      value: field(applyUrl, 0.9, lineContaining(text, applyUrl)),
      jd: jdUrl ? field(jdUrl, 0.9, lineContaining(text, jdUrl)) : none(),
    };
  }
  if (phones.length) {
    const raw = (text.match(PHONE_RE) ?? [])[0];
    return {
      method: field<ApplyMethod>('phone', 0.85, lineContaining(text, raw ?? '')),
      value: field(phones[0], 0.85, lineContaining(text, raw ?? '')),
      jd: jdUrl ? field(jdUrl, 0.9, lineContaining(text, jdUrl)) : none(),
    };
  }
  return { method: none(), value: none(), jd: jdUrl ? field(jdUrl, 0.9, null) : none() };
}

/**
 * D13 field 2 — where the application lands.
 *
 * A suggestion the poster confirms in one tap, never a silent classification:
 * calling a genuine hiring manager an "external recruiter" on their own post is
 * a meaningful slur, and the domain heuristic cannot tell the difference.
 */
export function inferDestination(method: ApplyMethod, value: string): { value: DestinationType; confidence: number } {
  const v = String(value ?? '').toLowerCase();

  if (method === 'via_loop') return { value: 'via_poster', confidence: 1 };
  if (method === 'phone') return { value: 'named_person', confidence: 0.7 };

  if (method === 'link') {
    if (PLATFORM_HOSTS.some((h) => v.includes(h))) return { value: 'third_party_platform', confidence: 0.85 };
    if (/\/(careers|jobs)\b/.test(v)) return { value: 'company_ats', confidence: 0.8 };
    return { value: 'company_ats', confidence: 0.55 };
  }

  const [mailbox = '', domain = ''] = v.split('@');
  if (RECRUITER_HINTS.some((h) => domain.includes(h))) return { value: 'external_recruiter', confidence: 0.75 };
  if (GENERIC_MAILBOXES.some((m) => mailbox === m || mailbox.startsWith(`${m}.`))) {
    return { value: 'company_ats', confidence: 0.9 };
  }
  return { value: 'named_person', confidence: 0.8 };
}

export function parsePost(text: string): ParsedPost {
  const raw = String(text ?? '');
  if (!raw.trim()) {
    return {
      title: none(), company: none(), locations: none(), experience: none(),
      compensation: none(), applyMethod: none(), applyValue: none(), jdUrl: none(),
      destination: none(), raw, overallConfidence: 0,
    };
  }

  const { method, value, jd } = parseRoute(raw);
  const destination = value.value && method.value
    ? (() => {
        const d = inferDestination(method.value!, value.value!);
        return field<DestinationType>(d.value, d.confidence, value.source);
      })()
    : none<DestinationType>();

  const parsed: ParsedPost = {
    title: parseTitle(raw),
    company: parseCompany(raw),
    locations: parseLocations(raw),
    experience: parseExperience(raw),
    compensation: parseCompensation(raw),
    applyMethod: method,
    applyValue: value,
    jdUrl: jd,
    destination,
    raw,
    overallConfidence: 0,
  };

  const scored = [parsed.title, parsed.locations, parsed.experience, parsed.applyValue];
  parsed.overallConfidence =
    Math.round((scored.reduce((sum, f) => sum + f.confidence, 0) / scored.length) * 100) / 100;

  return parsed;
}
```

```ts
/**
 * The two disclosure fields, and the sentence they combine into (D13).
 *
 * §5.1 calls the *Forwarded · External recruiter* line the single most useful
 * sentence on the platform: it lets a candidate decide in two seconds whether
 * to spend an hour, and it is exactly what a WhatsApp forward destroys. So it
 * is composed here, once, and no card writes its own.
 *
 * Composed rather than looked up: the rung supplies what the poster can do, the
 * destination supplies where the CV lands. Twenty hand-written strings would
 * drift the moment one rung's wording changed.
 */
import { RELATIONSHIP_RANK } from '../data/schema.ts';
import type { DestinationType, PosterRelationship } from '../data/schema.ts';

export interface DisclosureContext {
  posterName: string;
  companyName: string | null;
  contactName: string | null;
}

export interface DisclosureInput extends DisclosureContext {
  relationship: PosterRelationship;
  destination: DestinationType;
}

const BADGE_LABEL: Record<PosterRelationship, string> = {
  hiring_manager: 'Hiring manager',
  internal_can_refer: 'Internal · can refer',
  knows_contact: 'Connected · knows the contact',
  forwarded: 'Forwarded',
};

export function relationshipBadge(r: PosterRelationship): { label: string; rank: number } {
  return { label: BADGE_LABEL[r], rank: RELATIONSHIP_RANK[r] };
}

export function destinationLabel(d: DestinationType, ctx: DisclosureContext): string {
  switch (d) {
    case 'company_ats':
      return 'Company application';
    case 'external_recruiter':
      return 'External recruiter';
    case 'third_party_platform':
      return 'Third-party platform';
    case 'via_poster':
      return `Through ${ctx.posterName}`;
    case 'named_person': {
      const who = ctx.contactName ?? 'a named contact';
      return ctx.companyName ? `Direct to ${who} at ${ctx.companyName}` : `Direct to ${who}`;
    }
  }
}

/** Where the CV actually lands, as a clause. */
function destinationClause(d: DestinationType, ctx: DisclosureContext): string {
  switch (d) {
    case 'company_ats':
      return 'Your application goes into the company’s own hiring process.';
    case 'external_recruiter':
      return 'Your CV goes to an external search firm, which may retain it for other roles.';
    case 'third_party_platform':
      return 'Your application goes through a third-party jobs platform.';
    case 'via_poster':
      return `${ctx.posterName} will pass your profile on directly.`;
    case 'named_person':
      return ctx.contactName
        ? `Your CV goes straight to ${ctx.contactName}.`
        : 'Your CV goes straight to a named contact at the company.';
  }
}

export function disclosureSentence(input: DisclosureInput): string {
  const { relationship, destination, posterName, contactName } = input;

  // The four rungs the PRD works through by example keep their exact wording;
  // every other pair composes from the same two halves.
  if (relationship === 'hiring_manager') {
    return `${posterName} is hiring for their own team. Applying puts you in front of the decision-maker.`;
  }

  if (relationship === 'internal_can_refer') {
    return destination === 'via_poster'
      ? `${posterName} works here and will submit you as an internal referral.`
      : `${posterName} works here and can refer you. ${destinationClause(destination, input)}`;
  }

  if (relationship === 'knows_contact') {
    const who = contactName ?? 'the hiring contact';
    return destination === 'named_person'
      ? `${posterName} doesn't work here, but knows ${who}, who is hiring. Your CV goes straight to them — and ${posterName} can follow up for you.`
      : `${posterName} doesn't work here, but knows ${who}. ${destinationClause(destination, input)} ${posterName} can follow up for you.`;
  }

  return `${posterName} has no connection to this company. ${destinationClause(destination, input)} Nobody here can push your profile.`;
}
```

```ts
/**
 * Confirm-or-decay (D14).
 *
 * §5.1 names the defining failure of WhatsApp job forwarding: a filled role
 * still circulating three months later. A post therefore has to earn its place
 * on the board repeatedly rather than once.
 *
 * "I don't know" is a first-class answer, not a non-answer. A *Forwarded*
 * poster genuinely cannot know whether the role is still open, and forcing a
 * yes/no out of them would manufacture exactly the false confidence the clock
 * exists to remove — so it resets the confirmation clock without asserting the
 * post is open.
 */
import { daysBetween } from './time.ts';
import type { JobPost } from '../data/schema.ts';

export const CONFIRM_PROMPT_DAYS = [14, 28] as const;
export const DEFAULT_LIFE_DAYS = 30;
export const ARCHIVE_DAY = 45;

export type FreshnessState = 'fresh' | 'confirm_due' | 'unconfirmed' | 'filled' | 'archived';

export interface Freshness {
  state: FreshnessState;
  ageDays: number;
  daysSinceConfirmed: number;
  label: string;
  promptDue: boolean;
  shouldArchive: boolean;
}

export function freshnessFor(post: JobPost, now: number): Freshness {
  const ageDays = daysBetween(post.postedAt, now);
  const daysSinceConfirmed = daysBetween(post.lastConfirmedAt, now);

  if (post.archivedAt !== null) {
    return { state: 'archived', ageDays, daysSinceConfirmed, label: 'Archived', promptDue: false, shouldArchive: false };
  }

  if (post.confirmState === 'filled') {
    return { state: 'filled', ageDays, daysSinceConfirmed, label: 'Filled', promptDue: false, shouldArchive: true };
  }

  if (ageDays >= ARCHIVE_DAY) {
    return {
      state: 'unconfirmed', ageDays, daysSinceConfirmed,
      label: `Unconfirmed — last confirmed ${daysSinceConfirmed} days ago`,
      promptDue: false, shouldArchive: true,
    };
  }

  if (daysSinceConfirmed > DEFAULT_LIFE_DAYS) {
    return {
      state: 'unconfirmed', ageDays, daysSinceConfirmed,
      label: `Unconfirmed — last confirmed ${daysSinceConfirmed} days ago`,
      promptDue: true, shouldArchive: false,
    };
  }

  const promptDue = CONFIRM_PROMPT_DAYS.some((d) => daysSinceConfirmed >= d);
  if (promptDue) {
    return {
      state: 'confirm_due', ageDays, daysSinceConfirmed,
      label: `Posted ${ageDays} days ago — still open?`, promptDue: true, shouldArchive: false,
    };
  }

  return {
    state: 'fresh', ageDays, daysSinceConfirmed,
    label: ageDays === 0 ? 'Posted today' : `Posted ${ageDays} days ago`,
    promptDue: false, shouldArchive: false,
  };
}
```

```ts
/**
 * Duplicate detection across posters (§5.1).
 *
 * The same JD arriving from four alumni is normal, and §5.1 is explicit that it
 * should read as corroboration rather than clutter — several independent
 * posters raise a role's credibility. So duplicates merge into one card that
 * names the others, instead of being suppressed or listed four times.
 *
 * The key is the apply route plus the role title: the route is what actually
 * identifies a role across four differently-worded forwards.
 */

/**
 * Params that identify the forward, not the role. Everything else is kept:
 * `?utm_source=whatsapp` is noise, but `?jobId=456` is a different requisition.
 */
const TRACKING_PARAMS = [
  'utm_source', 'utm_medium', 'utm_campaign', 'utm_term', 'utm_content',
  'fbclid', 'gclid', 'ref', 'source', 'src',
];

const TITLE_SYNONYMS: [RegExp, string][] = [
  [/\bsr\.?\b/gi, 'senior'],
  [/\bjr\.?\b/gi, 'junior'],
  [/\bmgr\.?\b/gi, 'manager'],
  [/\bassoc\.?\b/gi, 'associate'],
  [/\bvp\b/gi, 'vice president'],
];

export function normaliseRoute(v: string): string {
  const raw = String(v ?? '').trim();
  if (!raw) return '';

  if (raw.includes('@') && !raw.startsWith('http')) return raw.toLowerCase();

  if (/^https?:\/\//i.test(raw)) {
    try {
      const u = new URL(raw);
      const host = u.host.toLowerCase().replace(/^www\./, '');
      const path = u.pathname.replace(/\/+$/, '');
      // Drop tracking params but KEEP the rest. Dropping the whole query string
      // makes `?jobId=123` and `?jobId=456` collide, merging two real openings
      // into one card and hiding one of them — the precise failure §2 blames
      // WhatsApp for. Sorted so param order never affects the key.
      for (const t of TRACKING_PARAMS) u.searchParams.delete(t);
      u.searchParams.sort();
      const query = u.searchParams.toString();
      return `${host}${path}${query ? `?${query}` : ''}`;
    } catch {
      return raw.toLowerCase();
    }
  }

  const digits = raw.replace(/\D/g, '');
  if (digits.length >= 10) {
    // Indian mobiles arrive as 8800029599, 08800029599 and +918800029599.
    // All three are one person; failing to fold them produces duplicate cards.
    if (digits.length === 12 && digits.startsWith('91')) return digits.slice(2);
    if (digits.length === 11 && digits.startsWith('0')) return digits.slice(1);
    return digits;
  }
  return raw.toLowerCase();
}

export function normaliseTitle(t: string): string {
  let out = String(t ?? '').toLowerCase();
  for (const [re, to] of TITLE_SYNONYMS) out = out.replace(re, to);
  return out.replace(/[^a-z0-9 ]+/g, ' ').replace(/\s+/g, ' ').trim();
}

/** A stable, readable key. Not cryptographic — collisions here are cheap. */
export function dedupeHash(applyValue: string, title: string): string {
  return `${normaliseRoute(applyValue)}::${normaliseTitle(title)}`;
}

export function sharerSummary(names: string[]): string {
  const list = names.filter(Boolean);
  if (!list.length) return '';
  if (list.length === 1) return `Also shared by ${list[0]}`;
  if (list.length === 2) return `Also shared by ${list[0]} and ${list[1]}`;
  return `Also shared by ${list[0]}, ${list[1]} +${list.length - 2}`;
}
```

```ts
/**
 * Board ordering (D16): connection rung, then freshness, then recency.
 *
 * Cold forwards are allowed and honestly badged — §5.0 shows they are a real
 * share of useful volume — but they do not get the top of the board. Ranking by
 * proximity rather than recency is what stops the board becoming the WhatsApp
 * scroll it replaces.
 */
import { freshnessFor } from './freshness.ts';
import { RELATIONSHIP_RANK } from '../data/schema.ts';
import type { JobPost } from '../data/schema.ts';

const FRESHNESS_ORDER: Record<string, number> = {
  fresh: 0,
  confirm_due: 1,
  unconfirmed: 2,
  filled: 3,
  archived: 4,
};

export function rankKey(post: JobPost, now: number): [number, number, number] {
  const f = freshnessFor(post, now);
  return [RELATIONSHIP_RANK[post.posterRelationship], FRESHNESS_ORDER[f.state] ?? 9, -post.postedAt];
}

/** Live posts only, best first. Archived and filled leave the board entirely. */
export function sortPosts(posts: JobPost[], now: number): JobPost[] {
  return posts
    .filter((p) => {
      const f = freshnessFor(p, now);
      return f.state !== 'archived' && f.state !== 'filled';
    })
    .map((p) => ({ p, k: rankKey(p, now) }))
    .sort((a, b) => a.k[0] - b.k[0] || a.k[1] - b.k[1] || a.k[2] - b.k[2])
    .map(({ p }) => p);
}
```

```ts
/**
 * The referral request state machine (§5.2).
 *
 * `stateOwner` is written on every transition rather than derived on read. The
 * tracker and the nudge engine both ask whose turn it is, and if they ever
 * computed it independently they could disagree — which would show up as the
 * product nagging the wrong person, the single fastest way to lose a referrer.
 *
 * Transitions are refused rather than corrected. A request that reaches an
 * impossible state is a bug worth surfacing, not one worth papering over.
 */
import { addDays } from './time.ts';
import { TERMINAL_REQUEST_STATES } from '../data/schema.ts';
import type { DeclineReason, ReferralRequest, RequestState } from '../data/schema.ts';

export class RuleViolation extends Error {
  code: string;
  constructor(message: string, code: string) {
    super(message);
    this.name = 'RuleViolation';
    this.code = code;
  }
}

export const RESPONSE_WINDOW_DAYS = 7;
export const SUBMIT_WINDOW_DAYS = 14;
export const OUTCOME_WINDOW_DAYS = 14;

export const OWNER_BY_STATE: Record<RequestState, 'seeker' | 'referrer' | null> = {
  sent: 'referrer',
  accepted: 'referrer',
  submitted: 'seeker',
  recruiter_contact: 'seeker',
  interviewing: 'seeker',
  declined: null,
  offer: null,
  rejected: null,
  no_response: null,
  expired: null,
  expired_unsubmitted: null,
  role_closed: null,
};

export const TRANSITIONS: Record<RequestState, RequestState[]> = {
  sent: ['accepted', 'declined', 'expired'],
  accepted: ['submitted', 'role_closed', 'expired_unsubmitted'],
  submitted: ['recruiter_contact', 'interviewing', 'offer', 'rejected', 'no_response'],
  recruiter_contact: ['interviewing', 'offer', 'rejected', 'no_response'],
  interviewing: ['offer', 'rejected', 'no_response'],
  declined: [],
  offer: [],
  rejected: [],
  no_response: [],
  expired: [],
  expired_unsubmitted: [],
  role_closed: [],
};

const REFERRER_ONLY: RequestState[] = ['accepted', 'declined', 'submitted', 'role_closed'];
const SEEKER_ONLY: RequestState[] = ['interviewing', 'offer', 'rejected'];
const EITHER: RequestState[] = ['recruiter_contact'];
const SYSTEM_ONLY: RequestState[] = ['expired', 'expired_unsubmitted', 'no_response'];

export function isTerminal(s: RequestState): boolean {
  return TERMINAL_REQUEST_STATES.includes(s);
}

export function canTransition(from: RequestState, to: RequestState): boolean {
  return TRANSITIONS[from]?.includes(to) ?? false;
}

export function actorMayTransition(role: 'seeker' | 'referrer' | 'system', to: RequestState): boolean {
  if (role === 'system') return SYSTEM_ONLY.includes(to);
  if (EITHER.includes(to)) return true;
  if (role === 'referrer') return REFERRER_ONLY.includes(to);
  return SEEKER_ONLY.includes(to);
}

/** Days the new owner gets before the first nudge lands. */
function windowFor(to: RequestState): number | null {
  if (to === 'accepted') return SUBMIT_WINDOW_DAYS;
  if (to === 'submitted' || to === 'recruiter_contact' || to === 'interviewing') return OUTCOME_WINDOW_DAYS;
  return null;
}

export function applyTransition(
  r: ReferralRequest,
  to: RequestState,
  role: 'seeker' | 'referrer' | 'system',
  at: number,
  opts: { declineReason?: DeclineReason } = {},
): ReferralRequest {
  if (!canTransition(r.state, to)) {
    throw new RuleViolation(`A request cannot go from ${r.state} to ${to}.`, 'illegal_transition');
  }
  if (!actorMayTransition(role, to)) {
    throw new RuleViolation(`A ${role} cannot move a request to ${to}.`, 'wrong_actor');
  }
  if (to === 'declined' && !opts.declineReason) {
    throw new RuleViolation('Give a reason so the seeker knows where they stand.', 'missing_decline_reason');
  }

  const owner = OWNER_BY_STATE[to];
  const window = windowFor(to);

  return {
    ...r,
    state: to,
    stateOwner: owner,
    declineReason: to === 'declined' ? (opts.declineReason ?? null) : r.declineReason,
    nextUpdateDue: window === null ? null : addDays(at, window),
    // A new owner starts with a clean slate; nudges chase the current turn.
    nudgeCount: 0,
    lastNudgedAt: null,
    updatedAt: at,
  };
}
```

`src/core/nudges.ts`:
```ts
/**
 * The nudge engine (§5.2).
 *
 * Under spec DL1 this carries more weight than the PRD gave it. D5's hard block
 * on new requests is gone, so nudging plus the tracker is now the *only*
 * mechanism keeping loops closed — §11's >70% closure rate is the number that
 * will tell us whether that was enough.
 *
 * The engine nudges exactly one person: whoever `stateOwner` says owes the next
 * update. Chasing both sides is how a referral network teaches people to ignore
 * its email.
 */
import { daysBetween } from './time.ts';
import { RESPONSE_WINDOW_DAYS, SUBMIT_WINDOW_DAYS, isTerminal } from './requests.ts';
import type { PostApplication, ReferralRequest, RequestState } from '../data/schema.ts';

export const SENT_NUDGE_DAYS = [3, 6] as const;
export const ACCEPTED_NUDGE_DAYS = [7] as const;
export const SUBMITTED_NUDGE_DAYS = [14, 30, 45] as const;
export const MAX_NUDGES = 3;
export const APPLICATION_PROMPT_DAY = 14;

function scheduleFor(state: RequestState): readonly number[] {
  if (state === 'sent') return SENT_NUDGE_DAYS;
  if (state === 'accepted') return ACCEPTED_NUDGE_DAYS;
  if (state === 'submitted' || state === 'recruiter_contact' || state === 'interviewing') return SUBMITTED_NUDGE_DAYS;
  return [];
}

/**
 * Days are measured from when the current state began, not from the last
 * nudge: the schedule is absolute, so a missed send does not push the whole
 * sequence back.
 */
export function nudgeDueFor(
  r: ReferralRequest,
  now: number,
): { due: boolean; target: 'seeker' | 'referrer' | null; nudgeNumber: number } {
  if (isTerminal(r.state) || r.stateOwner === null) return { due: false, target: null, nudgeNumber: 0 };

  const schedule = scheduleFor(r.state);
  if (r.nudgeCount >= Math.min(MAX_NUDGES, schedule.length)) {
    return { due: false, target: r.stateOwner, nudgeNumber: r.nudgeCount };
  }

  const elapsed = daysBetween(r.updatedAt, now);
  const nextThreshold = schedule[r.nudgeCount];
  if (nextThreshold === undefined) return { due: false, target: r.stateOwner, nudgeNumber: r.nudgeCount };

  return { due: elapsed >= nextThreshold, target: r.stateOwner, nudgeNumber: r.nudgeCount + 1 };
}

/** What the system should do on its own, if anything. */
export function autoAdvanceFor(r: ReferralRequest, now: number): RequestState | null {
  if (isTerminal(r.state)) return null;
  const elapsed = daysBetween(r.updatedAt, now);

  if (r.state === 'sent' && elapsed >= RESPONSE_WINDOW_DAYS) return 'expired';
  if (r.state === 'accepted' && elapsed >= SUBMIT_WINDOW_DAYS) return 'expired_unsubmitted';

  const outcomeStates: RequestState[] = ['submitted', 'recruiter_contact', 'interviewing'];
  if (outcomeStates.includes(r.state) && r.nudgeCount >= MAX_NUDGES) {
    const lastNudge = r.lastNudgedAt ?? r.updatedAt;
    if (daysBetween(lastNudge, now) >= 1) return 'no_response';
  }
  return null;
}

/** §5.1: one prompt, never blocking. A job board cannot fairly be gated. */
export function applicationPromptDue(a: PostApplication, now: number): boolean {
  if (a.outcome !== 'unknown') return false;
  if (a.promptedAt !== null) return false;
  return daysBetween(a.appliedAt, now) >= APPLICATION_PROMPT_DAY;
}
```

`src/core/capacity.ts`:
```ts
/**
 * Volume control (§7.1 referrer capacity; spec DL1).
 *
 * The seeker side is deliberately uncapped — no max open requests, no
 * per-company limit, no closure block. Supply is protected from the receiving
 * end instead: a referrer sets their own intake, and a seeker is never stopped
 * on the way out. That is the whole of DL1 in one file.
 *
 * The single retained guard is the duplicate *submission*, which is not about
 * supply at all: two alumni filing the same person for the same role costs a
 * referrer their bonus and creates an ATS conflict on the company's side (§8).
 */
import { normaliseTitle } from './dedupe.ts';
import { isTerminal } from './requests.ts';
import { daysBetween } from './time.ts';
import type { Member, ReferralRequest } from '../data/schema.ts';

const MONTH_DAYS = 30;

export function openRequestsFor(referrerId: string, all: ReferralRequest[]): ReferralRequest[] {
  return all.filter((r) => r.referrerId === referrerId && !isTerminal(r.state));
}

export function referralsThisMonth(referrerId: string, all: ReferralRequest[], now: number): number {
  return all.filter(
    (r) => r.referrerId === referrerId && r.state !== 'sent' && r.state !== 'declined'
      && r.state !== 'expired' && daysBetween(r.updatedAt, now) < MONTH_DAYS,
  ).length;
}

export function intakeCheck(
  referrer: Member,
  all: ReferralRequest[],
  now: number,
): { accepting: boolean; reason: string | null; autoDeclineMessage: string | null } {
  const decline = referrer.caps.autoDeclineMessage || null;

  if (!referrer.openToReferring) return { accepting: false, reason: 'not_open', autoDeclineMessage: decline };
  if (referrer.caps.paused) return { accepting: false, reason: 'paused', autoDeclineMessage: decline };
  if (openRequestsFor(referrer.id, all).length >= referrer.caps.maxOpen) {
    return { accepting: false, reason: 'at_capacity', autoDeclineMessage: decline };
  }
  if (referralsThisMonth(referrer.id, all, now) >= referrer.caps.maxPerMonth) {
    return { accepting: false, reason: 'monthly_cap', autoDeclineMessage: decline };
  }
  return { accepting: true, reason: null, autoDeclineMessage: null };
}

/**
 * Returns the existing submitted request, if this seeker is already in for this
 * role at this company. Only a real submission counts — several alumni *offering*
 * to refer the same person is fine and common.
 */
export function duplicateSubmissionGuard(
  seekerId: string,
  companyId: string,
  roleTitle: string,
  all: ReferralRequest[],
): ReferralRequest | null {
  const target = normaliseTitle(roleTitle);
  const submitted: string[] = ['submitted', 'recruiter_contact', 'interviewing', 'offer', 'rejected'];
  return (
    all.find(
      (r) => r.seekerId === seekerId && r.companyId === companyId
        && submitted.includes(r.state) && normaliseTitle(r.roleTitle) === target,
    ) ?? null
  );
}
```

```ts
import { useEffect, useState, useSyncExternalStore } from 'react';
import { runClock, subscribe } from '../data/store.ts';

/*
 * The store mutates in place and notifies, so object identity is not a usable
 * snapshot — a commit counter is. Registered at module load, before any
 * component mounts, and the store notifies in insertion order, so the counter
 * is always bumped before React reads it.
 */
let version = 0;
subscribe(() => {
  version += 1;
});
const snapshot = () => version;

export function useStoreVersion(): number {
  return useSyncExternalStore(subscribe, snapshot, snapshot);
}

/**
 * A "now" that advances, and advances the clock with it.
 *
 * Every freshness and nudge reading is a function of the current instant, so a
 * board left open would otherwise show posts frozen at page load — and a post
 * that should have decayed would keep its ranking.
 */
export function useNow(intervalMs = 60_000): number {
  const [now, setNow] = useState(() => Date.now());
  useEffect(() => {
    const id = setInterval(() => {
      const t = Date.now();
      runClock(t);
      setNow(t);
    }, intervalMs);
    return () => clearInterval(id);
  }, [intervalMs]);
  return now;
}
```

- [ ] **Step 1: Write the smoke script**

Render every screen to a string through Vite's SSR loader against the seeded store. A passing typecheck does not catch a bad store call, a null company on a confidential post, or a member with no employment — this does.

```js
/**
 * Render smoke test.
 *
 * Asserts that each screen renders at all, which is the failure this build is
 * prone to. It does not assert on markup.
 */
import { createElement as h } from 'react';
import { renderToString } from 'react-dom/server';
import { createServer } from 'vite';

const mem = new Map();
globalThis.localStorage = {
  getItem: (k) => (mem.has(k) ? mem.get(k) : null),
  setItem: (k, v) => mem.set(k, String(v)),
  removeItem: (k) => mem.delete(k),
  clear: () => mem.clear(),
};
globalThis.location = new URL('http://localhost:5174/');

const vite = await createServer({ server: { middlewareMode: true }, appType: 'custom', logLevel: 'error' });
const load = (p) => vite.ssrLoadModule(p);
const store = await load('/src/data/store.ts');
store.load();

const now = Date.now();
const noop = () => {};
let failed = 0;

const screens = [
  ['Board', '/src/ui/Board.tsx', 'Board', { now, onOpenPost: noop }],
  ['Tracker', '/src/ui/Tracker.tsx', 'Tracker', { now, onOpenRequest: noop, onOpenPost: noop }],
  ['Directory', '/src/ui/Directory.tsx', 'Directory', { onOpenCompany: noop, onRequestReferral: noop }],
  ['Requests', '/src/ui/Requests.tsx', 'Requests', { now }],
  ['Admin', '/src/ui/Admin.tsx', 'Admin', { now }],
  ['Profile', '/src/ui/Profile.tsx', 'Profile', {}],
  ['App', '/src/ui/App.tsx', 'App', {}],
];

for (const [label, path, name, props] of screens) {
  try {
    const mod = await load(path);
    const html = renderToString(h(mod[name], props));
    console.log(`  ok   ${label.padEnd(12)} ${String(html.length).padStart(6)} chars`);
  } catch (err) {
    failed += 1;
    console.log(`  FAIL ${label}: ${err.message}`);
  }
}

// D2, asserted rather than assumed: an unverified viewer's screens carry no data.
try {
  const pending = store.getState().members.find((m) => m.status === 'pending');
  store.setCurrentMember(pending.id);
  const { Board } = await load('/src/ui/Board.tsx');
  const html = renderToString(h(Board, { now, onOpenPost: noop }));
  const names = store.getState().members.filter((m) => m.status === 'verified').slice(0, 20).map((m) => m.name);
  const leaked = names.filter((n) => html.includes(n));
  if (leaked.length) throw new Error(`unverified viewer saw: ${leaked.join(', ')}`);
  console.log(`  ok   ${'D2 gate'.padEnd(12)} unverified viewer sees no member data`);
} catch (err) {
  failed += 1;
  console.log(`  FAIL D2 gate: ${err.message}`);
}

await vite.close();
console.log(failed ? `\n${failed} failed.` : '\nAll screens rendered.');
process.exit(failed ? 1 : 0);
```
